# Yacht Club Manager

Полноценное desktop-приложение яхт-клуба: гостевой каталог, клиентский кабинет, администрирование заявок, платежей, возвратов, причалов и обслуживания, погодный dashboard и аналитика.

Стек: Python 3.11+, PySide6, PostgreSQL 16, Docker Compose, psycopg 3, bcrypt, Pillow, Matplotlib, openpyxl и ReportLab. 

## Быстрый запуск в PyCharm

1. Откройте корневую папку проекта и выберите Python 3.11+ interpreter. Установите зависимости из requirements.txt через интерфейс PyCharm (Python Packages / Install requirements).
2. Установите и запустите Docker Desktop. При первом старте main.py создаст локальный .env, поднимет PostgreSQL через Compose, дождётся готовности БД и откроет окно приложения.
3. В конфигурации запуска PyCharm укажите Script path — main.py, Working directory — корень проекта.

Запуск из PowerShell тоже выполняйте из корневой папки проекта (в PyCharm — Terminal → значок папки проекта):

    cd "C:\Users\User\PycharmProjects\Cursach yacht"
    py -3.11 -m venv .venv-yacht
    .\.venv-yacht\Scripts\Activate.ps1
    python -m pip install -r requirements.txt
    python main.py

## Сборка для Windows

В PowerShell из корневой папки проекта выполните:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_windows.ps1 -UseLocalSettings

Сборщик использует Python 3.11 и отдельное окружение `.venv-build`. Если Python
установлен без лаунчера `py`, передайте путь к интерпретатору параметром
`-BasePython`. В конце сборщик выводит пути к исполняемому файлу и ZIP.
Оба результата размещаются в новой папке `dist/<номер сборки>/`.

На компьютере с уже настроенной базой параметр `-UseLocalSettings` копирует
текущий `.env` только в распакованную папку приложения. В ZIP входит
только шаблон `.env.example`. Для передачи на другой компьютер используйте
готовый ZIP, извлеките его целиком, запустите Docker Desktop и затем откройте
`YachtClubManager.exe`. Python и библиотеки включены в сборку. PostgreSQL
запускается в Docker, как при запуске из исходного кода.

Точка входа называется `main.py`; команды из `C:\Users\User` не найдут файлы проекта, пока вы не перейдёте в его папку.

Ручной запуск SQL-скриптов не требуется. При первом создании Docker volume Compose применяет sql/001_schema.sql — схему и функции, sql/002_roles_and_permissions.sql — отдельную роль приложения, sql/003_seed.sql — демонстрационные данные и sql/004_grants.sql — ограниченные права. При запуске приложения безопасно и повторно применяется sql/005_ports_and_pickup.sql: она добавляет порты и места отправления, сохраняя прежние данные. При повторном старте постоянный volume сохраняет базу.

Если Docker Compose недоступен, приложение показывает понятную ошибку и не завершает запуск аварийно. Для администрирования БД можно подключиться через pgAdmin 4 или DBeaver:

| Параметр | Значение по умолчанию |
| --- | --- |
| Host | 127.0.0.1 |
| Port | 55432 |
| Database | yacht_club_manager |
| Application user | yacht_app |
| Admin login | admin@yacht.local |

Пароли PostgreSQL генерируются при первом старте и сохраняются в локальном .env, который исключён из Git. Настройки можно изменить в .env. Пример находится в .env.example.

Если сохранённый Docker volume был создан до установки схемы, приложение установит схему и демонстрационные данные, создаст роль `yacht_app` и выдаст ей ограниченные права. Если роль уже есть, её пароль будет синхронизирован с локальным `.env`. Существующие данные при этом не удаляются.

## Что доступно в приложении

- Гостевой режим: стартовая страница, иллюстрированный каталог, карточки яхт, поиск, фильтры по типу/производителю/вместимости/каютам, сортировка, доступность по датам, услуги и последняя погода.
- Клиент: регистрация и вход, профиль, избранное, отправка заявки с пассажирами/услугами и снимком тарифов, история статусов, демо-оплата, заявка на банковский перевод, PDF-квитанции, уведомления и отмена заявки.
- Администратор: dashboard с выручкой, заявками и предупреждениями; очередь подтверждения и отказа; управление флотом и изображениями; клиенты и блокировка; тарифы; порты, фотографии, причалы и места стоянки; история размещения яхт; карта занятости; обслуживание; подтверждение платежей; частичные возвраты; выдача и возврат судна; аудит и безопасная SQL-консоль.
- Порт назначения заявки определяется по месту яхты на выбранный период. При подтверждении система назначает доступное совместимое место в том же активном порту; если такого места нет, заявку нельзя подтвердить, пока администратор не решит ситуацию. Клиент видит адрес и место отправления в уведомлении и карточке бронирования.
- Карта портов доступна клиенту и администратору. OpenStreetMap подключается при наличии сети; локальная интерактивная схема позволяет просматривать порты с координатами и информацию о местах при недоступности картографического сервиса. В учебную базу добавлены демонстрационные точки Ялты и Феодосии; у них явно указано, что это только точки карты, а не подтверждённые яхтенные стоянки. Старые причалы и бронирования общего демонстрационного порта однократно переносятся на Ялтинскую учебную точку, чтобы их было видно на карте.
- Погода: текущие данные и почасовой прогноз Open-Meteo, ветер/порывы/осадки/видимость, риск по порогам конкретных типов судов и хранение истории. Волны отображаются как «Нет данных», пока не подключён отдельный морской источник.
- Аналитика: выручка по месяцам с сравнением, спрос по яхтам, типам и статусам; загрузка флота и рейтинг яхт; экспорт XLSX/PDF.

Фотографии в исходной базе — явно помеченные иллюстрации проекта. Администратор может заменить их изображениями клуба; путь, подпись, alt-текст и порядок хранятся в БД. Клиентские платежи демонстрационные; банковские данные не собираются. Учебная квитанция не является фискальным чеком.

## Схема PostgreSQL

Подробная модель и обоснование 3НФ: [docs/ERD.md](docs/ERD.md). Демонстрационные сценарии: [docs/DEMO.md](docs/DEMO.md).

Представления: vw_boat_catalog, vw_active_reservations, vw_payment_summary, vw_monthly_analytics, vw_client_statistics, vw_boat_statistics.

Функции: fn_get_available_boats, fn_calculate_reservation_total, fn_get_client_balance, fn_get_monthly_revenue, fn_get_fleet_utilization, fn_get_boat_popularity.

Пересечение заявок одной яхты запрещено ограничением PostgreSQL EXCLUDE USING gist по диапазону tstzrange. Платежи, подтверждение статуса, запись истории и формирование квитанции выполняются транзакционно. SQL-консоль доступна только администратору; она разрешает один запрос SELECT/WITH в read-only transaction. У пользователя приложения нет прав DDL.

## Резервное копирование и восстановление

Выполняйте из корня проекта в PowerShell:

    ./scripts/backup.ps1
    ./scripts/restore.ps1 -InputPath './backups/yacht_club_manager_20261118_120000.dump'

Восстановление очищает и пересоздаёт объекты БД из выбранного дампа. Перед восстановлением сохраните текущую копию.


## Структура

- main.py — точка входа PyCharm и клиентский/административный интерфейс.
- yachtclub/ — настройки, подключения, безопасность, бизнес-логика, погода и PDF.
- sql/ — схема, роли, тестовые данные и права PostgreSQL.
- assets/boats/ — демонстрационные SVG-иллюстрации яхт.
- docker-compose.yml — PostgreSQL 16 и постоянный именованный volume.
- scripts/ — резервная копия и восстановление.
- docs/ — ER-модель, 3НФ, SQL-примеры и демонстрация.
- tests/ — модульные и PostgreSQL-интеграционные проверки.
